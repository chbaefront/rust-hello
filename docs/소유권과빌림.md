## 소유권(Ownership)과 빌림(Barrow)

---

- 러스트의 소유권 시스템은 메모리 안전성과 동시에 성능을 보장하기 위해 고안한 독특한 개념   
이 개념은 개발자가 명시적으로 메모리를 관리할 필요 없이, 컴파일 시점에 메모리 사용과 관련된 대부분의 오류를 방지하도록 해줌


- **각 값은 하나의 소유자만 가짐**
- **값이 소유권을 잃으면 자동으로 메모리에서 해제**
- **빌림(borrowing)을 통하여 값에 대한 일시적인 접근 허용**

```rust
fn main() {
    let s1 = String::from("Hello, Rust!");
    let s2 = s1;
    
    println!("{}", s2);
}
```

위 코드에서 s1 문자열 값을 s2 변수에 할당을 했습니다. 다른 프로그래밍 언어라면 s1, s2 동일하게 접근하고 값 출력이 가능한데 Rust에서는 s1에 대한 접근이 차단됩니다.
즉, 소유권이 s2로 이동되었기 때문입니다.

```rust
 // 스칼라 타입(integer, bool, char, float 등)은 크기가 컴파일 시점에 완전히 정해져 있으므로 실제 값 복사가 이뤄짐
let num1 = 1;
let num2 = num1;
println!("num1: {}, num2: {}", num1, num2); // 이거는 허용
```
위와 같이 스칼라 타입은 컴파일 시점에 크기가 고정되어 있으므로 복사가 일어나서 새로 할당된다.(서로 영향을 주지 않음)


```rust
{// 임의의 스코프
        let str = String::from("hello");
        println!("str: {}", str);
} // 변수 str이 스코프를 벗어나는 순간, 자동으로 메모리 해제
// println!("str: {}", str); // Cannot find value `str` in this scope [E0425]
```

소유권을 가진 변수가 자신이 선언된 스코프(Scope)를 벗어나면 Rust가 자동으로 메모리를 해제하며, 이 과정에서 drop 함수가 알아서 호출됩니다. 단, Copy타입(Copy 트레이트 구현 타입)은 drop 되지 않습니다.   
당연하겠지만, 스택에 생성되는 데이터는 함수 호출이 끝나면 스택에서 자동으로 pop되므로 특별한 해제 처리가 필요 없기 때문입니다.

(Rust 에서는 Copy 트레이트와 Drop 트레이트를 동시에 구현하는 것을 금지)

```rust
// 빌림을 통해 접근을 허용
// 불변 참조와 가변 참조
let s = String::from("frontend");
let r1 = &s;
let r2 = &s;
// r1.push_str(" developer"); // Cannot borrow immutable local variable `r1` as mutable
println!("r1: {}, r2: {}", r1, r2);

let mut ss = String::from("frontend2");
let r3 = &mut ss;
r3.push_str(" developer");
println!("r3: {}", r3);
println!("ss: {}", ss);
```

```rust
fn print(target_val: String) {
    println!("print: {}", target_val);
}

fn add_str(target_val: &mut String, add_str: String) {
    target_val.push_str(add_str.as_str());
}


// 함수 호출 시, 소유권 이동
let a = String::from("print");
print(a);
// println!("a: {}", a); // Value used after being moved [E0382]

// 함수 호출 시, 소유권 빌려주기
let mut b = String::from("print");
add_str(&mut b, " test".to_string());
println!("b: {}", b);
```

함수 호출(인자 전달)을 할 때도 스칼라 타입(기본형 타입)이면 소유권이 이동(Move)하지 않고 복사(Copy)

힙을 사용하는 타입 (String, Vec 등) -> 포인터를 포함하고 있어 메모리 해제(drop) 책임이 따르는 타입   
-> 함수에 값 그대로 넘기면 소유권이 함수 내부로 이동(Move)해 버립니다. 함수가 끝날 때 인자가 drop되므로 원본 변수는 더 이상 쓸 수 없게 됩니다.

**참조의 유효범위는 참조자가 생성된 시점부터 유효 범위를 벗어날 때 까지.**

### 클로저에서의 예시

```rust
    // 클로저
let add = |a: i32, b: i32| -> i32 { a + b };
let print_name = |name: String| println!("{}", name);
let print_name2 = |name: &String| println!("{}", name);

let aaa = 2;
let bbb = 3;
let result = add(aaa, bbb);
println!("result: {}({} + {})", result, aaa, bbb);

let name = String::from("홍길동");
let name2 = String::from("이순신");
print_name(name);
// println!("name: {}", name); // Value used after being moved [E0382]
print_name2(&name2); // 불변 빌림
println!("name2: {}", name2);

// 클로저는 외부 변수를 캡처
let target_print = String::from("print");
let print_name3 = || println!("{}", target_print);
print_name3();
println!("외부에서 재사용: {}", target_print); // 소유권이 그대로 있음

let mut count = 0;
let mut increment = || {
count += 1;
println!("클로저 내부 count: {}", count);
};
increment(); // 출력: 1
increment(); // 출력: 2

// 클로저 사용이 끝났으므로 외부에서 접근 가능
println!("외부에서 확인한 count: {}", count); // 출력: 2

let list = vec![1, 2, 3];
let print_list = || {
let my_list = list; // 소유권이 my_list로 이동
// borrow of moved value: `list` [E0382]
// Note: move occurs because `list` has type `Vec<i32>`, which does not implement the `Copy` trait
// println!("list: {:?}", list);
};
print_list();
// println!("{:?}", list); // borrow of moved value: `list`

// move 키워드 사용
let list2 = vec![1, 2, 3];
let print_list2 = move || {
println!("list: {:?}", list2);
};
print_list2();
// println!("{:?}", list2); // borrow of moved value: `list2`

let mut list3 = vec![1, 2, 3];
let mut print_list3 = || { // mut이 있어야 가변 빌림
list3.push(4);
println!("list3: {:?}", list3);
};
print_list3();
println!("list3: {:?}", list3); // move || 로 하면 소유권 이동되어서, 이부분 에러
```

- 클로저는 데이터를 변경하지 않고 출력하거나 검사할 때는 불변 빌림
- 클로저 내부에서 카운터를 올리거나 리스트에 요소를 추가할 때 가변 빌림
- `move` 키워드를 사용하면 강제로 소유권을 이동

```
불변 빌림: Fn
가변 빌림: FnMut
소유권 이동: FnOnce
```

클로저가 실행될 때 매개변수(파라미터)를 주고받는 규칙은 일반 함수 호출할 때의 소유권·빌림 규칙과 100% 동일합니다.   
오직 주변 환경의 변수를 훔쳐 오는 '캡처링(Capturing)' 메커니즘만 클로저 고유의 영역입니다.
